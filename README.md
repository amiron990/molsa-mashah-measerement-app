# מצפן רשויות מקומיות

מפת מדדים להערכת איכות עבודת המחלקות לשירותים חברתיים · אגף בכיר איכות, פיקוח ובקרה.

## מבנה

| קובץ | תפקיד |
|---|---|
| `index.html` | מסך תפיסת המדידה: עץ הנושאים, משפך המיפוי ומקורות הנתונים |
| `map.html` | סקירת המדדים: כרטיסי המדדים, הסינון, בורר רמת התצוגה וגרפי המגמה |
| `manage.html` | מסך ניהול המדדים — מוגן בסיסמה |
| `workshop.html` | כלי הסדנה. **אינו מקושר מהניווט** כרגע — אין סדנה פעילה |
| `assets/app.css` | מערכת העיצוב (מבוססת מסמך "עקרונות עיצוביים ופלטת צבעים") |
| `assets/data.js` | שכבת הנתונים — **נוצר אוטומטית, לא לערוך ידנית** |
| `assets/concept.js` | הלוגיקה של תפיסת המדידה **ושל סקירת המדדים** — קובץ אחד, כל מסך מצייר את מה שיש ב-DOM שלו |
| `assets/workshop.js` | הלוגיקה של כלי הסדנה — כתובת הדשבורד (`DASH_PATH`) ומאגר השאלות (`SCREENS`) |
| `assets/collect.js` | איסוף התשובות לגיליון — כאן מגדירים את `COLLECT_URL` |
| `assets/manage.js` | הלוגיקה של מסך הניהול |
| `tools/apps-script/` | הסקריפט שיושב בגיליון, והוראות ההקמה שלו |
| `tools/gen_data.py` | בונה את `assets/data.js` מקבצי ה-CSV |
| `_reference/` | הגרסה הישנה של כלי הסדנה, נשמרה כרפרנס בלבד |

## רענון הנתונים

הנתונים נבנים משלושה קבצי CSV:

| קובץ | מיקום | תוכן |
|---|---|---|
| `רשימת מדדים משחים.csv` | תיקיית האב (`../`) | טבלת ה-DIM של המדדים |
| `מספר אינדקטורים לפי נושא ותת נושא.csv` | תיקיית האב (`../`) | חמשת הנושאים ו-17 תתי הנושאים |
| `נתונים.csv` | **תיקיית הכלי** | כל סדרות העת, בשלוש רמות |

`נתונים.csv` מחזיק את שלוש הרמות בקובץ אחד: `Pop_Category_Heb` היא הרמה
(`ארצי` / `מחוז` / `נפה`) ו-`קטגוריה` הוא השם.

**שם לבדו אינו ייחודי** — «ירושלים» היא גם מחוז וגם נפה, עם סדרות שונות. לכן מפתח
הרמה ב-`SERIES` הוא `רמה§שם`, ו-`SCOPES` הוא מערך של `{key, name, level, …}` ולא של
מחרוזות. מפתוח לפי שם בלבד היה ממזג את השתיים בשקט.

**גם בתוך רמת הנפה יש שמות חוזרים** — «מזרח» ו«מערב» קיימות גם במחוז הדרום וגם בתל
אביב והמרכז. כשזה קורה הקובץ מקדים לשם הנפה את שם המחוז, `מחוז - נפה`
(`הדרום - מזרח`). `gen_data.py` מזהה קידומת כזו, שומר את המחוז ב-`parent` ואת השם
הקצר ב-`short`, והמסך מציג «מזרח» עם שם המחוז לצדו.

הקובץ מכנה מדד אחד בשם מאוחר מזה שברשימת המדדים (`אחוז תפוסה במסגרות בקהילה` מול
`אחוז תפוסה במסגרות`, מזהה 1031). הגישור הוא מפורש, במילון `RENAMES` שב-`gen_data.py`.

לאחר עדכון קובץ מקור:

```bash
python tools/gen_data.py
```

## מה מוצג

- **28 מדדים** בטבלת ה-DIM, מהם **18 מדדים ראשיים** (10 הנוספים הם פירוט איוש תקנים לפי תפקיד) ו-**15 מוצגים בסקירת המדדים**. שלושה מדדים ראשיים משויכים לנושא רקע שמחוץ לחמשת נושאי המפה ואינם מוצגים במסך.
- **28 מדדים** מגיעים עם סדרת עת — ארצית, ב-4 מחוזות וב-14 נפות (19 רמות תצוגה).
- בורר רמת התצוגה מקבץ את הרמות: «ארצי» בראש, ואחריו «מחוזות» ו«נפות» — הפרדה לפי רמה, לא עץ אב-בן.
- לרשימת המדדים שתי תצוגות: **כרטיסים** (ברירת המחדל — עמודה לכל נושא, המדדים שבתוכה זה מתחת לזה ותתי הנושאים מפרידים ביניהם) ו**טבלה**. מספר העמודות נגזר מהנושאים שנשארו אחרי הסינון — כרגע 3 מתוך 5, כי לשני נושאים אין מדדים במפה.
- תצוגה שלישית, **כרטיסים מפורט** (הנושאים זה מתחת לזה והכרטיסים בכל תת נושא נפרשים לרוחב), מוסתרת מאחורי `DETAILED_CARDS_ON` שב-`assets/concept.js` — הקוד שלה נשאר, וההחזרה היא שינוי הערך הזה בלבד. שתי תצוגות הכרטיסים נשענות על אותו `groupByTheme` ועל אותו `card()`, כדי שהסדר וההתנהגות לא יתפצלו ביניהן.
- **שיוך נפה למחוז מגיע משני מקורות.** כשנפה חולקת שם עם נפה במחוז אחר, קובץ הערכים מקדים לה את שם המחוז (`הדרום - מזרח`) והשיוך נגזר משם. לשאר הנפות אין במקור רמז למחוז, ולכן הטבלה נשמרת ידנית ב-`SUBDIST_PARENT` שב-`tools/gen_data.py`. בשני המקרים התוצאה היא שדה `parent` ב-`SCOPES` — מפתח הסקופ של המחוז, לא השם. כרגע כל 14 הנפות משויכות; נפה שתיפול בין הכיסאות פשוט לא תסמן מחוז במסך.
- מודאל המדד מציג שלושה מקטעים: ההגדרה, הערך וגרף המגמה, ולאחריהם **פילוח לפי מחוז ופילוח לפי נפה** — שני גרפי עמודות שבהם *כל* המחוזות ו*כל* הנפות מוצגים תמיד, ללא תלות בבורר רמת התצוגה. שלוש דרגות סימון: הבחירה עצמה בכחול מלא, מה שקשור אליה בשיוך (המחוז שמעל הנפה שנבחרה, או הנפות שתחת המחוז שנבחר) בכחול בהיר, וכל השאר באפור. כל העמודות בגרף נלקחות מאותו חודש — האחרון שיש בו נתון באותה רמה — ומסודרות מהגבוה לנמוך.
- `CUTOFF` ב-`tools/gen_data.py` חותך את הזנב של סדרות שבהן שינוי באופן הרישום יוצר קפיצה שאינה שינוי בשטח. שני מדדי פניות הציבור (1034, 1035) נחתכו שם בעבר בסוף 2025, כשהזנב שלהם היה תוצר של הפסקת דיווח; קובץ המקור עודכן מאז והסדרות רצות הלאה כרגיל, ולכן הן מוצגות במלואן.
- מספרי משפך המיפוי (156 → 60 → 32 → 18) לקוחים ממצגת המתודולוגיה ומוגדרים ב-`tools/gen_data.py` (משתנה `funnel`).

## שני המסכים הציבוריים

`index.html` ו-`map.html` טוענים את **אותו** `assets/concept.js`. הקובץ מצייר רק את מה
שקיים ב-DOM של הדף: העץ, המשפך והמקורות בראשון; רשימת המדדים, הסינון ובורר רמת
התצוגה בשני. לחיצה על תת נושא בעץ עוברת ל-`map.html?theme=…&sub=…` עם הסינון מוגדר.

## דירוג המשתמשים

בכניסה למסך המשתמש מתבקש לציין שם ונפה. נאספים שני סוגי משוב:

1. **דירוג מדד** — 1–5 כוכבים והערה חופשית, בכרטיס המדד.
2. **חיבוב תת נושא** — לייק / דיסלייק על כל אחד מ-17 תתי הנושאים במפת הנושאים, כדי לזהות אילו תתי נושאים בכל נושא חשובים למשתמשים. לחיצה חוזרת על אותו כפתור מבטלת את הסימון.

- הכול נשמר ב-`localStorage` של הדפדפן תחת המפתח `kyd_molsa_compass_v1` (`ratings` למדדים, `subvotes` לתתי הנושאים, במפתח `נושא§תת נושא`).
- כפתור **"ייצוא הערכות"** מוריד CSV אחד (עם BOM, נפתח נכון באקסל) עם עמודת **"סוג רשומה"** — `מדד` או `תת נושא` — כך ששני סוגי המשוב ניתנים לניתוח יחד:

  `סוג רשומה, שם המשתמש, נפה, נושא, תת נושא, מזהה מדד, שם המדד, דירוג (1-5), סימון תת נושא (1 חשוב / -1 פחות), הערה, עודכן`

- **לשליחה לשרת:** הגדירו כתובת במשתנה `SUBMIT_URL` בראש `assets/concept.js`. כל שמירה תישלח אליה כ-POST עם גוף JSON, במקביל לשמירה המקומית. בגוף הבקשה שדה `kind` מבחין בין `indicator` (עם `stars`/`note`) לבין `sub` (עם `vote` בערך 1 או 1-).

### הטמעת הדשבורד ו-HTTPS

`biportal` מוגש ב-HTTP. דפדפן לא מתיר לדף HTTPS להטמיע מסגרת HTTP (mixed content),
ולכן **בגרסה שרצה ב-Azure Static Web Apps הדשבורד לא ייטען לתוך המסגרת**. זו מגבלה
בדפדפן: אין הגדרה ב-Azure, כותרת HTTP או `staticwebapp.config.json` שמבטלת אותה, וגם
proxy לא יעזור כי ל-Azure אין גישה לרשת הפנימית.

**מצב שני חלונות** — הפתרון שמובנה בכלי. כשההטמעה נכשלת מוצע לפתוח את הדשבורד בחלון
נפרד (`window.open`), פעולה שאינה כפופה למגבלת ה-mixed content. אז השאלות תופסות את כל
רוחב החלון, ובראשן סרגל עם הבאה-לחזית / רענון / החזרה-לתוך-הדף. הבחירה נשמרת
ב-localStorage. מצמידים את שני החלונות עם `Win + ←` ו-`Win + →`.

פתרונות נוספים, לפי סדר עדיפות:

1. **להריץ את הכלי מכתובת HTTP** — אז ההטמעה עובדת כרגיל.
   - לסדנה: לחיצה כפולה על **`start-http.bat`**. הוא מגיש את התיקייה ב-HTTP, פותח את
     הדפדפן, ומדפיס גם את הכתובת ברשת המקומית כדי שמשתתפים אחרים יוכלו להתחבר
     (`http://<כתובת-המחשב>:8770/workshop.html`). לפתיחת הפורט למשתתפים, פעם אחת כמנהל:
     `netsh advfirewall firewall add rule name="KYD workshop 8770" dir=in action=allow protocol=TCP localport=8770`
   - לשימוש קבוע: אירוח התיקייה על שרת פנימי ב-HTTP (IIS). ראו למטה.
### אירוח ענני ב-HTTP (Azure Storage static website)

Azure Static Web Apps מחייב HTTPS ואי אפשר לכבות זאת — לכן הדשבורד לא ייטען שם
במסגרת. **Azure Storage static website** כן מאפשר HTTP, ברגע ש-"Secure transfer
required" מכובה, והוא אירוח סטטי בענן בעלות זניחה.

הדרך המהירה, בלי להתקין דבר — Azure Cloud Shell (bash) בפורטל:

```bash
git clone https://github.com/amiron990/molsa-mashah-measerement-app.git
cd molsa-mashah-measerement-app
bash tools/deploy-http-storage.sh
```

הסקריפט יוצר קבוצת משאבים וחשבון אחסון עם `--https-only false`, מפעיל אירוח סטטי,
מעלה את הקבצים ומדפיס את כתובת ה-HTTP. לעדכון — `git pull` והרצה חוזרת.

הכתובת ציבורית וללא הצפנה. להגבלת גישה לכתובות ה-IP של המשרד בלבד:

```bash
az storage account network-rule add -g <RG> --account-name <SA> --ip-address <CIDR>
az storage account update -g <RG> -n <SA> --default-action Deny
```

> ייתכן ש-Azure Policy בארגון אוסר יצירת חשבון אחסון ללא Secure transfer. במקרה כזה
> צריך חריג מצוות הענן, או ללכת על האירוח הפנימי שלמטה.

### אירוח פנימי ב-IIS (הפתרון הרוחבי)

הכלי הוא אתר סטטי — HTML/CSS/JS בלבד, בלי שרת אפליקציה ובלי בסיס נתונים. די בכך:

1. על שרת פנימי כלשהו: Server Manager → Add Roles and Features → **Web Server (IIS)**.
2. להעתיק את תוכן התיקייה ל-`C:\inetpub\workshop` (בלי `_reference/` ובלי קובצי המקור).
3. IIS Manager → Sites → Add Website: שם, נתיב התיקייה, פורט 80 עם hostname ייעודי
   (למשל `bi-tools`) או פורט פנוי אחר.
4. רשומת DNS פנימית לשם שנבחר, והרשאות קריאה ל-`IIS_IUSRS` על התיקייה.

התוצאה: `http://bi-tools/workshop.html` — HTTP מול HTTP, ההטמעה עובדת לכל משתמש ברשת
בלי הגדרה במחשב שלו. לעדכונים: `git pull` על השרת, או העתקה מחדש של התיקייה.

2. **מדיניות דפדפן ארגונית** — `InsecureContentAllowedForUrls` ב-Edge/Chrome, עם
   הכתובת של האתר ב-Azure. IT דוחפים אותה ב-GPO והדשבורד נטען במסגרת גם ב-HTTPS.
   ידנית לכל משתמש: מנעול בשורת הכתובת ← הגדרות אתר ← Insecure content ← Allow.
3. **HTTPS ל-Report Server** — SSL binding ב-Report Server Configuration Manager עם
   תעודה שסומכים עליה בדומיין. הפתרון הנקי; כתובת ההטמעה כאן תלוית-פרוטוקול
   (`//biportal/...`) ולכן תעבוד מיד.

## איסוף התשובות לגיליון

כל מה שמשתתף ממלא נשמר בדפדפן שלו **וגם** נשלח לגיליון Google, כך שאין תלות בכך שכל אחד
יזכור לייצא CSV בסוף.

- **הקמה חד-פעמית:** [`tools/apps-script/README.md`](tools/apps-script/README.md) — יצירת
  גיליון, הדבקת הסקריפט ופריסתו כ-Web App. בסיום מתקבלת כתובת שמסתיימת ב-`/exec`.
- **חיבור:** משבצים אותה ב-`COLLECT_URL` שבראש [`assets/collect.js`](assets/collect.js).
  כל עוד השדה ריק — האיסוף מושבת והכלי עובד בדיוק כרגיל, בלי שגיאות.
- `COLLECT_TOKEN` שם חייב להיות זהה ל-`TOKEN` שבראש `Code.gs`.

**מה נשלח:** דירוגי מדדים, לייק/דיסלייק על תתי נושאים, תשובות הסדנה (כולל שאלות ההמשך
וסימוני כן/לא לכל נושא), ורישום כניסה — כולם עם שם המשתתף, הנפה ומזהה משיב קבוע.

**איך זה עומד בתנאי סדנה:** כל שינוי נכנס לתור ב-`localStorage` ונשלח משם במנות. נפילת
רשת לא מאבדת דבר — התור שורד גם סגירת דפדפן ומתרוקן בכניסה הבאה. בפס הניווט יש חיווי:
"נשמר" כשהכול נשלח, "ממתין לשליחה · N" כשיש תור, ולחיצה עליו שולחת מיד.

השליחה היא `Content-Type: text/plain` בכוונה: זו בקשה "פשוטה" שאינה מפעילה preflight של
CORS — ש-Apps Script אינו יודע לענות לו. עם `application/json` הבקשות היו נחסמות בדפדפן.

## ניהול המדדים

[`manage.html`](manage.html) הוא מסך נפרד לצוות המתודולוגיה. הוא עובד מול שלוש לשוניות
נוספות **באותו גיליון** של תשובות הסדנה, שמקים [`tools/apps-script/Manage.gs`](tools/apps-script/Manage.gs):

| לשונית | תפקיד |
|---|---|
| `אינדיקטורים` | מקור האמת של המדדים — עמודה לכל שדה שקיים ב-`data.js`, ועוד סטטוס, אחראי, גרסה ושרשרת החלפות |
| `הערות ודיון` | פריטי דיון עם סטטוס טיפול, תגובות והחלטה |
| `יומן שינויים` | מי שינה מה, מתי ולמה |

**מה המסך עושה:** טבלת מדדים עם חיפוש וסינון, חלונית עריכה לכל מדד (כולל הורדה רכה —
הסטטוס משתנה ל«יורד» והשורה נשמרת), טיפול בהערות, ותצוגת היומן. כל כתיבה דורשת סיבה,
ונרשמת ביומן עם השם שהוקלד בשער הכניסה.

**ההערות מהסדנה נמשכות פנימה אוטומטית:** כל הערה חופשית שמשתתף השאיר (`ratings.הערה`,
`answers.פירוט`) נכנסת ל`הערות ודיון` עם סטטוס «פתוח», כדי שמישהו יטפל בה. המשיכה
אידמפוטנטית — הרצה חוזרת אינה מכפילה שורות, ומשתתף ששינה את דעתו מעדכן את ההערה הקיימת.

**השינויים מגיעים למסך תפיסת המדידה.** `index.html` נצבע מיד מ-`assets/data.js`, ובמקביל
מושך את הרשימה מהגיליון (`action: 'indicators'`, מוגן בטוקן הסדנה) ומצייר מחדש. אם אין רשת
או שהלשונית ריקה — המסך נשאר עם `data.js` ולא נשבר. שתי הסתייגויות: לְמדד שנוצר בגיליון אין
סדרה היסטורית (הסדרות נשארות ב-`data.js` לפי מזהה) ולכן לא יוצג לו גרף מגמה, ומדד בסטטוס
«יורד» נעלם מהתצוגה.

`assets/data.js` נשאר מקור האמת ההתחלתי ואינו נכתב מהמסך. הגישור חזרה ידני — כפתור
«ייצוא מדדים» מוריד את הלשונית בפורמט המערך של `INDICATORS`, ומשם מעדכנים את קובצי המקור
של `gen_data.py`.

**הקמה:** סעיף 6 ב-[`tools/apps-script/README.md`](tools/apps-script/README.md) — הדבקת
`Manage.gs`, קביעת סיסמת ניהול והרצת `mSetup`. בלי הסיסמה המסך אינו מציג דבר.

## דירוג המשתתפים — כבוי

הדירוג בכוכבים על מדדים והסימון 👍/👎 על תתי נושאים מוסתרים כרגע: אין סדנה פעילה. המתג הוא
`RATING_ON` בראש [`assets/concept.js`](assets/concept.js) — שינוי ל-`true` מחזיר את שניהם,
והדירוגים שכבר נאספו לגיליון נשמרים.

שער הכניסה (שם + נפה) **הוסר** מהמסך, ולא רק הוסתר. הפעלה מחדש של הדירוג תצריך להחזיר דרך
זיהוי כלשהי, אחרת הדירוגים יגיעו לגיליון בלי שם משיב. בורר «רמת תצוגה» (ארצי / נפה) נשאר —
הוא כלי אנליטי ואינו קשור לסדנה.
